# 角色天赋二选一

旧天赋树、前置节点、永久力量/生存加点和被动升级已移除。沿用Boss奖励、休息点、事件以及已有开局奖励的获取入口。Boss、休息点和事件的单角色奖励从所有未满天赋的角色中等概率随机抽取，允许连续选中同一角色；开局奖励仍随机两名不同角色。从该角色未获得的天赋中随机展示两个候选，选择一个保留至本局结束。仅剩一个天赋时展示唯一选项；全部获得后不再分配天赋奖励。

候选项保存在角色数据的 `TalentOffer` 中，打开、关闭界面或读取存档不会刷新。旧 `TalentPoints` 字段仅作为待选次数保存，界面不再提供加点。旧存档中已投入的天赋数量转为待选次数（不超过新池剩余数量），撤销旧天赋的生命上限加成；不再计算旧力量、生存与被动升级。

Boss、休息点和事件的获奖角色统一使用 `GameInfo.CreateTalentPointRewardRng`。本局种子、区域、节点类型和队列编号先派生节点种子，再通过 MurmurHash3 finalizer 混合后创建随机器，避免相邻队列种子在只取首个随机数时产生相关性。事件的天赋抽取也与其他事件资源的随机数消耗分开。相同状态下预览、领取和读档结果一致；修复会改变旧算法下尚未领取奖励的获奖角色，不引入防连出或轮抽规则。

每场战斗开始时，选中的天赋作为持久Buff附加在所属角色身上，具有名称和效果提示。战斗计数在每场战斗重新开始，消耗计数在同场战斗内跨回合保留。常驻触发要求所属角色存活；战斗外治疗读取已获得的天赋。

夜莺被动「夜光」改为己方每回合开始时向共享手牌加入1张利刃，遵守手牌上限；直接生成卡牌不受无法抽牌影响。移除原零费攻击牌伤害加成。旧夜莺天赋及候选按原池顺序映射到新天赋，保留已获数量和当前候选。

实现入口：`GameInfo.Talents.cs` 管理天赋池、候选与迁移，`TalentChoiceView.cs` 提供共享选择界面，`Battle.Talents.cs` 管理战斗Buff与触发，`GameInfo.TalentHealing.cs` 管理战斗外治疗。行动预览同步处理伤害、易伤、治疗、消耗增力、消耗群伤、进入隐身增力及首次力量共享；其他消耗效果超出模拟范围时标记为估算。

2026-11-08 经用户授权，仅对天赋抽取进行了离线复现与统计检查，直接编译工作区的随机数、天赋与奖励源码，使用 Godot 节点及无关数据依赖的替身。原算法完整复现种子 `767536437` 的五次发放；对 20 万个均匀采样种子，第二区域前两个休息点的同角色重复率由 46.5605% 降至 33.2375%（理论 33.3333%），四个连续休息点全给同一人的比例由 6.4605% 降至 3.6990%（理论 3.7037%）。另检查连续整数种子、Boss 与休息点组合、事件，以及预览/领取一致性、满额排除和候选序列化保留。修复后通过 196 项功能检查和 136 项统计判据。未构建游戏项目或启动 Godot，未验证实际 UI 交互。
