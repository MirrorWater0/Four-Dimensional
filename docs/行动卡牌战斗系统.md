# 行动卡牌战斗系统

## 玩法规则

- 角色常驻牌为行动牌；攻击牌、无色牌、玩家特殊牌、能力牌和敌方意图沿用即时效果。
- 带有“即时”词条的牌打出时立即结算，不安装进行动区；利刃和防御专注带有该词条。
- 从手牌手动打出，将原卡牌安装到所属角色的行动区。只在安装时付费，效果首次在当前玩家回合结束执行，此后每个玩家回合结束执行一次。
- 每角色初始 2 个行动卡槽，上限 4 个，可在 Battle 的 `ActionCardSlotsPerCharacter` 中调整。行动区按安装时间从旧到新排列，满槽时自动卸载最早安装的牌，新牌追加到最右侧，不再弹出替换选择。抓起所属角色的行动手牌时，待卸载旧牌抬起并显示橙色边框和“即将卸载”提示；放回、取消或确认出牌后清除提示。实际安装开始时旧牌立刻复用手牌弃牌动画从当前位置飞入弃牌堆，其他牌平滑让位，新牌从手牌释放位置飞入行动槽。费用不足、目标选择取消或眩晕阻止安装时不卸载旧牌。
- 已安装行动牌悬停时小卡保持原尺寸、小幅抬起，并显示独立的完整卡牌详情；小卡复用手牌的蓝色悬停遮罩。抓起手牌或进行手牌选择时行动牌暂停悬停与普通点击，避免抢占鼠标输入；满槽提示仅标出自动卸载的最旧牌，不处理选牌点击。
- 护卫等友方目标在安装时手动选择，后续持续作用于该目标。目标失效后自动选取生命比例最低的合法友方，同生命比例按站位选择。常驻卡原默认敌方单体目标统一使用 `HostileTargetReference.RandomPreview`（可预览的随机目标），无需在安装时手动选择敌人。其他卡牌的默认敌方目标及显式指定敌方首位的单目标，在出牌时均手动选择敌人，卡牌描述保持不变；全体及明确后排的目标规则保持不变。破击移除格挡与伤害使用同一选定目标。
- 常驻牌的可预览随机目标在手牌及行动区准备阶段确定，每个玩家回合开始重新抽取；同回合重复悬停、回合末预览与实际执行共用该次选择，不因查看预览而推进随机序列。目标失效时重新选择合法目标；回合模拟中尚未发生的转火标注为估算。随机单体只高亮该次选中的目标，重新抽取仍可能选中同一名敌人。
- X 费用牌记录安装时投入的能量，后续效果和预览使用该记录。行动区不进入抽牌、弃牌洗牌循环；战斗结束清空，局外卡组不变。

## 消耗 X

`ExhaustAfterExecutions` 是技能的执行次数上限，0 表示没有次数限制。所有原来带消耗的卡牌已改为 **消耗 1**。

安装不是执行；每次正常触发扣一次消耗次数，回响的额外执行不扣次数。先完成原效果和回响，再扣次数；剩余次数为 0 时进入消耗堆，并触发原消耗相关被动。X 费用牌计划内部的多段攻击/循环仍算一次完整执行。眩晕阻止效果时不扣次数。即时牌同样使用执行计数，因此消耗 1 在首次原效果及其回响结算后移出。从抽牌堆打出的卡牌、拾音及其他安装牌额外触发仍各扣一次消耗次数。

已安装行动牌执行次数耗尽时，在行动区当前位置复用手牌消耗动画和音效。先将卡牌当前显示位置、缩放与旋转复制到独立动画层，再移除行动区卡牌并让其余牌平滑让位；动画不会因槽位被复用或最后一张牌移除后行动区隐藏而中断。回合末自动执行和安装牌额外触发均走同一消耗动画路径。

提前替换尚有次数的行动牌时进入弃牌堆，剩余次数跟随卡牌实例 ID，再抽到同一实例不会重置次数。动态添加的原 `ExhaustAfterUse` 关键词对应消耗 1。虚无表示回合结束在手牌中时消耗，优先于保留；附加保留、固有保留和工具箱保留均不能阻止虚无消耗。

## 结算结构

`Skill.Effect()` 处理手动出牌生命周期：付费、出牌事件和出牌类 Buff，再安装行动牌或执行即时计划。

`Skill.ExecuteInstalledActionAsync()` 只处理持续效果计划，不再付费或重复触发出牌事件。行动牌按角色站位执行，每个角色的牌从右到左（新牌先、旧牌后）结算，整轮使用队列快照；眩晕阻止该角色的一次执行。安装时获得的回响额外执行在首次成功执行时生效；回响不扣消耗次数，也不会被原效果耗尽次数提前拦截。预览同样先模拟原效果和全部回响，再记录一次消耗次数。

玩家回合顺序为：回合开始 → 手动出牌 → 行动区效果 → 剩余手牌弃置 → 回合末 Buff。单张牌的完整计划仍在效果来源作用域中执行，击杀后的后续效果不因提前结束战斗而被截断。

行动牌触发时，需要选择手牌或牌堆卡牌的效果仍由玩家手动选择并确认，包括留音添加保留、弃牌、消耗、变化、检索和预测筛牌。结算暂停等待选择完成，再继续后续效果和行动牌；结束回合期间也保留选牌输入。原本明确随机的效果继续随机处理。

打出类型牌步骤从共享抽牌堆取出指定类型的1张卡，免费打出并按正常规则弃置或消耗；常驻牌免费安装，攻击牌等即时牌正常结算后进入弃牌/消耗区。默认取该类型的第一张，明确随机的效果随机取牌；没有匹配牌时不生效，不自动洗牌，也不指定角色。

侵袭从整个共享抽牌堆随机打出1张攻击卡，保留卡牌归属，不限制队友站位；需要选择目标时随机选择，没有攻击卡时不生效。

终奏和战术号令单独使用 `TriggerInstalledCardsStep`，从右到左触发选定友方的安装牌各一次，终奏随后卸下全部安装牌，战术号令随后消耗全部安装牌。沿用安装时记录的友方目标和 X 投入，计入执行次数，正常处理眩晕和消耗，不消耗首次自动执行的额外次数；同一额外触发链内每张安装牌最多触发一次，正在执行的牌不会被递归触发。含打出类型卡效果的安装牌也可以触发。可以选择没有安装牌的角色，此时不生效。

行动牌预览模拟当前安装的行动牌，按角色站位、从右到左的槽位顺序及技能步骤依次计算；支持多段、X 投入、力量变化、易伤、格挡、免伤、反伤、复活和击杀后转火。眩晕与消耗次数只在副本状态中模拟，不更改战斗。

敌人血量右侧只显示小剑与预计生命伤害数字，原来的“行动牌总伤”面板已移除。血条中预计被扣除的部分显示为半透明橙红色，按当前生命和最大生命计算，不修改实际血量或受伤缓冲条。已被格挡吸收的伤害不计入扣血区域。

角色格挡标记上方显示蓝色 `+X`，表示本轮行动牌预计新获得的格挡总数，不包含已有格挡，也不是结算后剩余格挡；按实际目标汇总自身、护卫、群体与召唤物格挡，并模拟生存成长、X 投入、回响和灯塔分享。考虑 999 格挡上限。数值为 0 时隐藏，当前没有格挡时也能显示非零预览。两类预览只在玩家出牌阶段显示，结束回合、角色死亡或对应效果被移除后隐藏。

小剑数字、蓝色格挡预览和血条扣血区域与实际格挡共用显隐动画：出现时从 1.8 倍缩回原尺寸并在 0.2 秒内淡入，退场复用格挡图标的残影扩散。只有显隐状态变化时播放，定时刷新和数值更新不会重启动画；初始化与场景清理即时隐藏。

回合结算预览会按相同顺序模拟安装牌额外触发，并在副本中累计执行次数、消耗和眩晕；打出抽牌堆卡牌的效果涉及牌堆变化，标注为估算，预览不实际取牌或执行。自定义回调、召唤、条件分支及未完整模拟的 Buff 会在悬停提示中标注“估算”；每次预览最多模拟 4096 个效果/命中，超出标注“部分预览”。

无色卡保留打出时即时执行的行为，不安装、不占槽位。行动牌安装先压缩至微小卡片，向槽位反方向上甩并回钩冲入槽位；飞行中卡片顶部始终朝向速度方向，入槽后才旋转转正、放大过冲并收稳。普通攻击次数及临时攻击系统已移除，仅保留旧 Buff 枚举编号以兼容历史标识。

## Inspector 布局参数

伤害数字、蓝色格挡预览与血条预览的布局直接写在 `character/CharacterTemplate.tscn` 的 `LifeBar` 下：`ActionDamagePreview`、`ActionBlockPreview`、`ActionDamagePreviewFill`。可在场景中调整位置、字号、颜色和小剑尺寸；节点默认隐藏，可在编辑器临时显示来调整样式，运行时由预览结果控制显隐。

打开 `battle/Battle.tscn`，选择 **ActionCardsLayer/ActionCardsUi**：

行动牌与悬停详情使用角色所在 CanvasLayer 的上一层；地图战斗中角色在第 4 层、行动牌在第 5 层，低于第 9 层的塞牌展示。独立运行战斗时对应第 0 层和第 1 层。

| 参数 | 用途 |
| --- | --- |
| OwnerOffset / RackWidth | 相对角色站位的整体偏移和行动区宽度 |
| CardScale / CardStep | 现有卡牌 UI 的缩放和横向间距，间距越小重叠越多 |
| LayoutMoveDuration | 新增、移除或重排时已有卡牌的让位时长，默认 0.24 秒；0 为即时布局 |
| FitCardsToWidth / ContentOffset | 自动压缩间距适配宽度、卡牌内容偏移 |
| ShowShortNames / ShortNameFontSize / ShortNameGap / ShortNameHeight | 小卡下方额外名称默认隐藏；可调整显示、字号和位置 |
| HoverLift / HoverDuration | 悬停抬起高度及动画时长 |
| PreviewPosition / PreviewScale / PreviewHintGap | 完整卡牌预览的位置、缩放及提示间距 |
| InstallWindupDuration / InstallFlyDuration | 安装蓄势和飞行时间 |
| InstallArcHeight / InstallPullback | 回钩轨迹高度、起飞前后拉距离 |
| InstallFlightScale / InstallTrailWidth | 起飞前缩小后的尺寸（默认 0.035，约 8×13）、拖尾宽度 |
| InstallImpactScale | 入槽后放大过冲倍率 |

参数在编辑器和运行时均生效。正式场景中的三个 Rack 默认显示 3 张编辑器预览牌；运行时只显示实际安装的卡牌。布局以角色站位为锚点，不随受击或攻击动画位移抖动。

独立组件 `battle/UIScene/ActionCardRack.tscn` 也导出了对应参数，另有 `PreviewCardCount`、`OwnerKey`、`OwnerName`。放在正式战斗中时，由 ActionCardsUi 的参数统一控制。小卡和完整悬停预览都复用 `BattleHandCard.tscn` / `SkillCard`。已有卡牌按实例保留当前显示位置，新增与移除时平滑让位，连续变更从当前动画位置接着移动；让位不会中断新卡入槽后的转正放大。

## 运行检查

构建：`dotnet build tower.sln --no-restore`。

在 Godot 中分别打开以下场景并按 F6，控制台须出现明确的 PASS：

- `tools/ActionCardRegression.tscn`：安装、实例归属、连续执行、护卫目标、X 投入、消耗 1/2、换槽、取消退款、实际手牌队列及两个玩家回合。
- `tools/TurnEndAttackRegression.tscn`：行动牌总伤预览与真实结算对比、预览无副作用、多段/力量成长/X/转火/反伤/眩晕。
- `tools/ActionCardInstallationPreview.tscn`：安装动画独立预览，点击重播；传入 `-- --installation-capture` 可保存连续帧并检查归位。
- `tools/ActionCardsUiPreview.tscn`：交互式布局原型。传入 `-- --action-cards-capture` 可自动检查 2～5 张牌、悬停、固定预览和窗口缩放。

行动区当前是战斗内状态，没有新增中途战斗存档格式。回归场景使用 WarmupMode 的真实 Battle/角色场景，截图保存到 `tmp/action_cards_battle`；布局原型使用静态截图背景，保存到 `tmp/action_cards_ui`。这是功能回归，完整流程与长期数值平衡仍需正常游戏试玩。

两个战斗回归场景退出时仍会报告 Godot/Spine 资源清理提示，来源尚未定位；功能断言的 PASS 不代表已经验证了资源生命周期。带鼠标交互的可视回归请逐个运行，避免多个游戏窗口同时产生鼠标事件干扰截图检查。
