# 卡牌数值 Resource 与图鉴编辑

卡牌平衡数值的唯一来源是 `data/skill_tuning/**/*.tres`。技能 C# 只保留效果逻辑和参数读取，不再保存同名数值的默认值；旧卡牌 JSON 和从 C# 重新生成卡牌数值的流程已移除。

## 在游戏图鉴中编辑

进入卡牌图鉴，点击一张卡牌，右侧的「卡牌数值」面板会列出其参数。面板选择框也包含基础牌、衍生牌、状态牌和敌方技能。

参数按卡牌类型显示：所有卡牌隐藏敌方费用，敌方技能隐藏玩家费用。敌方技能预览不展示费用。隐藏的费用参数仍保留在 Resource 中，应用或保存时不会丢失。

- 修改输入后，点击「应用」让当前游戏会话读取新值。上方效果说明、图鉴卡面和战斗技能缓存随后刷新。
- 从 Godot 编辑器运行时，「保存到项目」直接写回该卡牌的 `.tres`。这就是下次运行、Inspector 编辑和游戏导出所使用的正式定义。
- 导出后的游戏显示「保存到本地」，写入 `user://skill_tuning/{SkillID}.tres`。本地资源覆盖项目定义，重启仍生效；内置的 `res://` 不会被写入。
- 「恢复项目数值」删除对应本地覆盖，并撤销本次尚未保存到项目的调整。已经保存到项目的数值就是新的项目基准；若要撤回项目修改，使用版本管理。
- 切换卡牌会放弃尚未应用的输入。应用后的值保留在当前会话，只有保存才会持久化。

执行计划和预览缓存包含数值版本。活动战斗的技能、手牌、已安装的行动牌以及敌人意图还会统一刷新；进行中的队伍行动结束后刷新活动实例，已支付费用等战斗状态保留在技能实例中。

## 数据结构

- `CardTuningResource.cs`：一张卡的 `SkillKey`、显示名称和整数参数字典 `Values`。
- `CardTuningCatalog.cs` / `data/skill_tuning/catalog.tres`：显式引用全部卡牌资源，确保导出时保留这些依赖。
- `SkillTuning.cs`：加载、编辑草稿应用、持久化、本地覆盖、参数校验和版本管理。
- `CardTuningParameters.cs`：中文参数名称和输入约束。
- `Skill.Tuning.cs`：`V("参数名")` 读取 Resource，不接受每张卡牌各自的代码默认值。已有卡牌缺少字段时会自动补齐；未登记的卡牌资源仍需创建。
- `TuningParameterSchema.cs`：从当前编译后的代码识别卡牌和敌人的参数引用，包含回调、异步方法和继承的技能实现。
- `TuningResourceRepair.cs`：同步字段清单并持久保存，补齐新增字段、移除废弃字段，保留仍在使用的参数值。

`EnergyCost` 是玩家费用，`-1` 表示 X 费用。`EnemyEnergyCost` 是遗留兼容字段：当前敌方意图执行豁免费用，图鉴不提供该字段的编辑或费用展示。`ExhaustAfterExecutions` 表示执行几次后消耗，0 表示不消耗。旧本地覆盖与编辑草稿中的意图冷却字段会在加载、应用或保存时自动清理。

资源只存基础定义；角色归属、升级状态、临时费用、已支付能量和技能执行计数等仍属于技能实例。UI 布局定义在 `Menu/Encyclopedia.tscn`，参数行按选中资源动态生成。

## 新增卡牌或参数

1. 按现有流程注册技能 ID 和实现类。
2. 复制同类卡的 `.tres`，修改 `SkillKey`、`DisplayName` 和 `Values`；不要在 C# 添加对应的数值默认值。
3. 在 `catalog.tres` 中添加这个资源的外部引用，并加入 `Cards` 数组。旧 ID `DeSurviveSkill` 使用 `ShockWave` 的同一份资源。
4. 新参数通过 `V("参数名")` 或 `private int 参数名 => V(nameof(参数名));` 读取。通用效果构建器的默认参数只是逻辑结构，卡牌中的伤害、格挡、属性倍率、攻击次数等已显式读取资源。
5. 有需要时在 `CardTuningParameters` 中添加中文名称和约束。重新编译运行后，加载 Resource 时会识别新增的 `V("参数名")` / `V(nameof(参数名))` 并创建缺失字段；无需先执行对应战斗效果。普通整数初始化为 0，约束要求至少为 1 的除数等参数初始化为 1。请随后在图鉴修改为实际需要的数值。

加载时保留通用字段，并以当前技能实现中的参数引用为准同步清单：删除某个参数的所有 `V(...)` 引用并重新编译运行后，项目资源、本地覆盖和之后应用或保存的旧草稿都会移除该废弃字段。本地独有的旧字段不会再补回项目。旧本地覆盖缺少项目的新参数时沿用项目值，仍在使用的参数保留已有修改。技能 ID 别名沿用同一份参数清单。

从编辑器运行时，字段同步写回项目 `.tres`，同时更新已有本地覆盖；导出游戏写入 `user://`。自动保存只同步字段清单，不会把当前会话里仅「应用」、尚未保存的其他调整一起写入。无法写入时保留会话内的同步结果并提示手动保存；图鉴根据数值版本刷新参数列表。

参数名使用字符串常量或 `nameof`。如果某个技能使用无法静态识别的动态参数名，或无法读取其编译代码，会提示并保留该技能已有字段，避免误删；敌人参数引用无法完整识别时同样保留敌人已有字段。识别过程不执行战斗逻辑，导出游戏无需携带 C# 源码。

调试模式下，F9 只重载磁盘资源及敌人配置，不会从代码生成卡牌数值。`EnableDevelopmentTuningAutoReload` 开启时仍可检测外部文件修改。旧 `scripts/export_skill_tuning_from_source.ps1` 为兼容保留名称，仅显示迁移提示，不再从代码生成数值文件。

敌人角色生命、属性与被动参数现也使用 `EnemyTuningResource`，可在敌人图鉴编辑，见 `ENEMY_ENCYCLOPEDIA.md`。旧 `user://skill_tuning/*.json` 和 `skill_tuning.dev.json` 不再参与卡牌加载。
