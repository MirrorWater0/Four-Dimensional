# 敌人图鉴与数值编辑

从百科首页或左侧导航进入「敌人图鉴」。当前收录 21 个敌人及战仆召唤物，可按名称、被动或技能搜索。右侧展示头像、生命、力量、生存、被动、意图循环和技能；技能分别标记为随机池、固定流程和临时插入，也可编辑其数值。

右侧直接点击「基础属性与被动」或技能名称按钮；当前编辑的技能名称显示在数值列表上方：

- 基础属性：生命上限、初始力量、初始生存、基础力量加成和基础生存加成。
- 被动参数：该敌人实际使用的层数、恢复量、触发间隔、召唤数量等。没有数值参数的被动只展示说明。
- 技能参数：伤害、格挡、倍率、层数等，字段清单随当前编译后的技能参数引用同步，数值保存在技能 Resource 中。敌方意图执行豁免费用，玩家费用和遗留敌方费用字段均隐藏，技能说明也不展示费用。

修改后点击「应用」使当前会话读取新值；点击「保存到项目」或「保存到本地」持久保存。每次操作只处理当前选中的属性或技能。切换敌人或编辑项会放弃未应用的输入。

从 Godot 编辑器运行时，保存直接写回项目 `.tres`；导出后的游戏保存到 `user://`，重启仍有效。「恢复项目数值」删除当前编辑对象的本地覆盖，并撤销未保存到项目的调整。已经保存到项目的改动应使用版本管理撤回。

应用后图鉴刷新说明。活动战斗在当前行动结算结束后刷新对应定义：保留临时属性增减、已损失生命、技能执行计数、已支付费用等状态。开场被动不会重新执行；新的开场参数从下次战斗生效。地区、精英等遭遇倍率继续按原规则应用。

## 循环意图配置

在敌人的 `EnemyRegedit` 派生类中，`SkillIDs` 只定义随机意图池；`IntentionCycle` 定义循环流程，替代原来的 `OpeningIntentionSkillIDs`：

```csharp
SkillIDs = [SkillID.WarAttack, SkillID.WarSurvive, SkillID.WarSpecial];
IntentionCycle = [SkillID.WarAttack, SkillID.WarSurvive, random, SkillID.WarAttack];
RandomizeIntentionCycleStart = true; // 默认关闭；设为 true 时随机选择循环起点。
IntentionCycleInsertions = [
    (SkillID.WarSpecial, 3), // 第 3 回合临时插入一次。
    (SkillID.WarSurvive, 6), // 第 6 回合再插入一次。
];
```

流程顺序为攻击 → 生存 → 从随机池选一次 → 攻击 → 回到第一步。`RandomizeIntentionCycleStart` 默认 `false`，固定从第一项开始；设为 `true` 时，每个敌人初始化时等概率选择一个数组位置作为起点，只随机一次，随后按配置顺序循环。使用战斗意图随机数源，相同种子和初始化顺序可复现起点；空流程或单步流程不消耗起点随机数。可以重复技能、连续写多个 `random`，也可以完全不含随机段。`random` 是基类提供的标记；在类外配置时使用 `EnemyIntentionStep.Random`，不占用技能 ID。固定技能无需加入随机池，仍会出现在图鉴、战斗技能说明和数值刷新中。

`IntentionCycleInsertions` 是可选的 `(SkillID SkillId, int Turn)[]`，默认空数组。每项表示到指定回合临时插入一次固定技能：

- 回合从该敌人入场后的第一轮意图开始，按敌人意图在回合结束时的刷新次数计数，从 1 开始；与主循环长度、随机起点相互独立。
- 插入占用一个行动回合，主循环暂停，结束后接回原本应执行的循环步骤。例如主循环 `A → B → C`，第 3 回合插入 `X`，实际为 `A → B → X → C → A → B`。
- 按回合数升序处理；同回合多项按配置顺序逐回合处理。每项只结算一次，不会随主循环重复；可用不同回合配置同一技能多次。
- 眩晕回合照常计数，但保留当前意图且不消耗插入项；因此错过时机的插入会在保留意图结算后依次补上。重复刷新当前意图也不会提前消耗插入项。
- 插入技能遵循固定步骤规则；不能执行时该回合无意图，结算后消耗该项并恢复流程，不替换为随机技能。回合小于 1 或技能为 `SkillID.None` 的项会忽略。
- 插入技能无需加入 `SkillIDs` 或 `IntentionCycle`，会自动进入敌人技能列表，支持图鉴展示、技能数值编辑和战斗数值刷新；是否进入随机池仍由 `SkillIDs` 决定。

未指定流程时默认 `[random]`；空流程也按每次随机处理。现有敌人已配置下面的循环，Death 保留原循环，并在第 10 回合临时插入一次「终末武装」：自身获得30点格挡和10点力量，之后接回原循环。流程结构目前在敌人 C# 配置中编辑，图鉴展示流程并编辑技能数值。

每次行动结算推进一步，末尾回到第一步；眩晕阻止技能执行时保留当前步骤及已选意图。随机段在有其他可选技能时避免连续重复；固定段严格服从配置顺序。随机池为空或没有可用技能时该段无意图，行动后继续下一步；固定技能不可执行时同样不替换为随机技能。

## 当前意图设计

下表每行按从左向右的顺序循环，末尾回到第一步；只有显式开启 `RandomizeIntentionCycleStart` 的敌人会随机选择开场位置。「随机」从该敌人的现有 `SkillIDs` 池选一次。普通敌人侧重短循环和成长，精英增加蓄势与爆发连段，War、Havoc 使用六步循环。技能数值和原随机池保持原配置，固定步骤决定自身释放频率。

| 敌人 | 循环 | 设计目的 |
| --- | --- | --- |
| Evil | 流影二段 → 扭曲 → 流影二段 → 随机 | 双击试探后成长，维持短攻防节奏。 |
| FearWorm | 梦魇缠绕 → 恐惧咬噬 → 潜伏 → 随机 | 先单体压力，再全阵易伤；潜伏留出蓄势窗口。 |
| Armon | 矩阵斩击 → 矩阵护盾 → 矩阵过载 → 随机 | 将阵营格挡支援、牌堆干扰和过载成长串起来。 |
| Arrogance | 虚无追击 → 暗黑吞噬 → 双重压制 → 双重压制 → 随机 | 开场眩晕后蓄势，铺易伤后连续压制。 |
| AlienBody | 异体冲击 → 异体护壳 → 异体冲击 → 随机 | 削生存后护壳成长，再进攻。 |
| RedHusk | 护壳重生 → 聚合压缩 → 重拳突刺 → 随机 → 重拳突刺 | 每五步补护壳，成长后施加全阵压力。 |
| Ferociouess | 凶恶冲击 → 骨骼免疫 → 狂暴 → 随机 | 免疫阶段铺易伤，随后双段全阵爆发。 |
| Turbine | 循环 → 涡轮冲击 → 随机 → 超压模式 → 涡轮冲击 | 支援邻位后进入额外打出攻击卡的超压阶段。 |
| BlackHawk | 裂羽连袭 → 夜幕回翔 → 黑羽风暴 → 随机 → 裂羽连袭 | 隐身进攻、治疗支援和全阵风暴交替。 |
| Inexorability | 存续封缄 → 命定压制 → 随机 → 终局律令 | 蓄势压制，以全阵律令结束一轮。 |
| GraveWraith | 蚀骨噬咬 → 骨壳蜷护 → 冥骸觉醒 → 蚀骨噬咬 → 随机 | 削生存、施加易伤，再以攻击配合吸血被动。 |
| VoidAcolyte | 空壳蓄势 → 空洞刺击 → 虚空灌注 → 随机 | 成长后输出，周期性污染抽牌堆。 |
| VoidRotor | 裂刃斩击 → 蚀甲压制 → 虚界灌注 → 裂刃斩击 → 随机 | 虚弱、晕眩干扰与多段斩击轮换。 |
| HollowBulwark | 闭合 → 空壳 → 壁刃冲击 → 随机 → 壁刃冲击 | 翻倍开场格挡，筑垒后进入输出阶段；壁刃冲击在攻击后，每拥有5点格挡获得1点力量，向下取整且不消耗格挡。 |
| MarrowReaver | 裂髓斩 → 骨壳蓄力 → 双刃蚀髓 → 随机 → 裂髓斩 | 全阵压迫之间留出蓄力窗口，再集中蚀髓。 |
| FearElite | 惊惧凝视 → 蜷缩异相 → 梦魇扩散 → 随机 → 惊惧凝视 | 利用开场恐惧，蓄势后扩散并恢复生命。 |
| AngerElite | 裂镰 → 伏身 → 狂怒弧刃 → 随机 → 裂镰 | 铺易伤后弧刃爆发，保留进攻型随机追击。 |
| EnvyElite | 觊觎刺击 → 藏锋 → 夺辉 → 随机 | 削生存、虚弱干扰与夺取力量连成一轮。 |
| Havoc | 裂壳横扫 → 天灾之证 → 崩坏回响 → 裂壳横扫 → 随机 → 天灾之证 | 第三步固定爆发配合默认三回合灾厄脉冲，末尾防御。 |
| Death | 双魂裁决 → 终焉宣告 → 死寂 → 断魂；第10回合临时插入一次终末武装 | 终末武装使自身获得30点格挡和10点力量，插入结束后继续原循环。 |
| War | 全军出击 → 死亡行军 → 逝者军势 → 全军出击 → 随机 → 逝者军势 | 建立战仆、扩军、保护召唤物，再进攻整备。 |
| WarThrall | 冲锋陷阵 | 召唤者行动后反复冲锋。 |

潜伏、矩阵护盾、狂暴、夜幕回翔和骨壳蓄力原来没有进入对应随机池，本次作为固定步骤启用；仍不加入随机池。随机段可能选择其他攻击、成长或防御技能，因此实际一轮压力会波动。以上为按技能逻辑设计的初版节奏，尚未进行实战平衡验证。

## 数据来源

- `data/enemy_tuning/{EnemyKey}.tres`：基础属性与被动参数的唯一项目定义。
- `data/enemy_tuning/catalog.tres`：显式引用全部敌人资源，保留导出依赖。
- `data/skill_tuning/enemy/**/{SkillID}.tres`：敌方技能的唯一数值定义，与卡牌数值编辑共用。
- `user://enemy_tuning/{EnemyKey}.tres`、`user://skill_tuning/{SkillID}.tres`：导出游戏的本地覆盖。
- `EnemyCatalog.cs`：敌人配置工厂，包含普通、精英、Boss 和战仆。
- `Menu/Encyclopedia.tscn`：编辑器可见的敌人面板布局。

原敌人 JSON 已移除；旧 `enemy_tuning.dev.json` 和 `user://enemy_tuning/*.json` 不再加载。基础属性与被动不再保留各敌人的 C# 数值默认值。旧导出脚本不再从源码生成任何数值表。

已登记的敌人 Resource 缺少字段时会自动补齐：普通数值初始化为 0，生命上限和已有约束要求为正的触发间隔等初始化为 1。加载时从当前编译代码识别 `EnemyTuning.GetRequiredInt("敌人ID", "参数名")`（也支持 `nameof`）和技能的 `V("参数名")`，无需先触发对应被动或技能。自动生成的数值需要在图鉴按实际设计修改。

删除某个被动或技能参数的全部代码引用并重新编译运行后，加载时会清理项目资源和本地覆盖中的废弃字段；应用、保存旧草稿时也会清理。五个通用基础属性始终保留，本地旧字段不会再补回项目。无法完整识别动态参数名或编译代码时会提示并保留已有字段，避免误删。

编辑器运行时自动写回项目 Resource，导出游戏写入本地 Resource；旧本地配置会合并项目新增字段并保留仍在使用的参数值。自动保存只同步字段清单，不会同时保存其他尚未保存的会话调整。写入失败会提示，当前会话仍可继续读取同步后的字段。缺少整个敌人资源或 ID 无效时仍需修正登记。
