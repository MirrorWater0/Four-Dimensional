# 战斗效果执行队列

战斗通过 `Battle.ExecuteBattleEffectAsync` 顺序结算技能、技能步骤、目标效果、被动、遗物和道具。队列保存 `Func<Task>`，到执行时才启动工作，避免把已经运行的 Task 放进“待执行列表”。Godot 节点操作始终在主线程完成，不使用 `Task.Run`。

## 顺序与动画

- 外部入口按入队顺序执行。出牌队列保留手牌提交、抽牌堆打出优先级和卡牌展示的生命周期，`Skill.Effect` 将玩法结算交给战斗队列。
- 当前效果产生的事件回调通过 `QueueBattleEffect` 入队，在当前步骤结束或下一子步骤开始前结算。抽牌堆打出、条件、循环和回响通过同一异步调用链执行子效果，子效果无需等待外层效果退出。
- 批量消耗先移除原来的牌并整理手牌，再逐张结算消耗护盾、循环利用、消耗天赋与恶魔。每张牌产生的印牌、格挡共享等子回调全部完成后，才处理下一张消耗事件，避免新生成的牌混入本批移除操作。
- 耗尽之盾在任意卡牌被消耗时触发，包括无归属状态牌；每个持有者的每层使己方全阵（含召唤物）获得2点格挡，多个持有者分别结算。
- 虚弱立场在己方全队回合结束时结算一次：统计存活敌方（含召唤物）当前虚弱总层数，每个持有者的每层使己方全阵（含召唤物）获得该总层数×1点格挡；多个持有者分别结算。施加虚弱不再立即触发格挡，逐目标预算与烽火共享规则保持不变。
- 消耗事件逐张保留卡牌的真实归属；循环利用每层从被消耗卡牌所属角色的完整非基础牌池中随机生成一张卡加入手牌，生成牌也归属该角色。无归属牌不触发循环利用，但仍触发其他消耗效果；当前行动角色只作为界面上下文，不会补为卡牌归属。
- 出牌队列在临时绑定执行角色前保存原始归属，归堆或取消出牌返还手牌时恢复；瘟疫等无归属状态牌不会因为打出而获得执行角色的归属，取消选牌返还手牌也不会为状态牌补充归属。
- 归堆和消耗动画的消耗判定显式读取本场战斗保存的实体卡牌执行次数与附加消耗关键字，不依赖卡牌归属。瘟疫恢复无归属后仍会在执行一次后消耗，触发耗尽之盾等通用消耗效果，但不会触发要求卡牌有归属的循环利用。
- 效果前后都不等待整副手牌动画或布局停稳。抽牌和塞入手牌的布局更新只错开一帧；槽位通过卡牌身份同步，正在运动的牌从当前位置继续追随新的布局目标。
- 行动牌安装在安装状态写入时启动飞行动画，和后续回调结算重叠。卸下、消耗、回合末弃牌、塞入牌堆及治疗的展示动画自行播放；数值与牌堆按效果顺序更新。
- 每批塞牌和回合末弃牌动画持有独立的预览卡与任务列表，完成后清理自己的节点。安装飞行期间，出牌流程保留原卡，结束后再归还卡池；安装槽位换牌会取消旧的到达展示。
- 攻击命中时机、玩家选牌和同一张卡的节点使用仍由相应流程协调。回合末冻结布局时，新生成的手牌留到下一回合展示。
- AOE 共享一次起手，每一段攻击在同帧启动所有存活目标的命中动画，再按目标顺序结算伤害和被动。多段群攻按整轮推进，段与段之间保留节奏间隔；不会逐个目标重复等待起手或命中动画结束。
- 技能计划保留击杀后的后续步骤，战斗结束检查仍在整张牌结算后进行。效果队列运行期间的自动战斗结束检查延迟到队列清空。
- 濒死结算开始后，胜负判定等待死亡触发、复生状态和召唤物清理全部完成；复生成功的角色仍参与战斗。嵌套濒死结算全部退出后重新检查胜负，避免分帧等待复生时提前结束战斗。

## 每帧预算

Battle 检查器的 **Effect Queue / Effects Per Frame** 默认值为 `1`，可以设置为 `1–8`。效果开始前检查当前帧预算，超过预算时等待下一帧；多个目标的伤害、增益、格挡与治疗依次执行。持续行动的外层编排使用 `consumeFrameBudget: false`，由内部步骤消耗预算。大量抽牌的卡牌创建分帧进行，重叠的塞牌动画也共享每帧预览卡创建上限。

预算限制的是效果启动数量，不能中途拆开任意一段同步代码。新增复杂效果应拆成步骤或逐目标子效果，避免在单个委托中一次创建大量节点。

消耗护盾、印牌全队格挡、虚弱立场、天赋全队格挡和烽火共享均按目标消耗预算；循环利用每层的随机抽选与卡牌入手也在预算内执行。共享所得格挡不会再次触发烽火。随机印牌直接从角色已注册的完整非基础牌池抽选，不再为筛选候选牌逐个构造技能实例。`QueueBattleEffect` 的纯编排入口也可指定 `consumeFrameBudget: false`，由实际执行数值变化或创建卡牌的子效果计入预算。

## 新效果入口

需要等待完成的调用：

```csharp
await battle.ExecuteBattleEffectAsync(async () => {
    await target.GetHurt(damage, source);
}, "效果名称");
```

同步事件回调：

```csharp
battle.QueueBattleEffect(() => target.IncreaseProperties(PropertyType.Power, 1, source), "被动名称");
```

`ResolvePendingBattleEffectsAsync` 在效果内部结算当前效果产生的回调，在外部等待玩法队列完成。它不等待视觉动画。不要在委托内部自行并行启动战斗结算；展示动画可以在对应状态更新时启动，并自行负责节点生命周期。

撤退、失败或场景退出会停止队列，释放外部等待者并清除未执行项；执行异常记录效果名称，并传给等待该项的调用者。
